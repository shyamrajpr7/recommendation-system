# CineRead — AI Movie Recommendation & Cinema Ticket Booking

A full-stack cinema ticketing web app: vector-similarity movie search with
grounded AI explanations, showtime browsing, interactive seat selection, and
Razorpay payment — all powered by a FastAPI backend with a Streamlit frontend.

## Features

- **🎟️ Now Showing** — browse the current movie catalog, pick a date + showtime,
  select seats on an interactive seat map (available / occupied / blocked), and
  book tickets.
- **💳 Razorpay checkout** — real payment links when `RAZORPAY_KEY_ID` /
  `RAZORPAY_KEY_SECRET` are set; a simulated payment flow when they are not.
- **✨ AI Search** — semantic retrieval (sentence-transformers + FAISS) with
  grounded natural-language explanations generated by **Grok (xAI)**.
- **🤖 AI Assistant** — chat concierge grounded in the live catalog, theaters,
  and showtimes; answers questions and guides the booking flow.
- **🎫 My Booking** — look up any booking by its reference and view the e-ticket.

## Architecture

```
┌──────────────┐   HTTP    ┌─────────────────────────────────────────────────┐
│  Streamlit   │ ────────► │  FastAPI                                        │
│  Frontend    │ ◄──────── │  /recommend  vector search + AI explanations     │
└──────────────┘   JSON    │  /movies /showtimes /seats                      │
                           │  /bookings  create + Razorpay payment link      │
                           │  /bookings/{ref}/verify  confirm after payment  │
                           │  /chat       AI concierge (grounded in data)    │
                           └─────────────────────────────────────────────────┘
```

- **Frontend**: Streamlit (`frontend/app.py`)
- **Backend**: FastAPI (`backend/app/main.py`)
- **Retrieval**: `sentence-transformers` (`all-MiniLM-L6-v2`) + FAISS inner-product index
- **Metadata & ticketing**: SQLite — movies, theaters, screens, showtimes, bookings
- **LLM**: Groq (primary, `qwen/qwen3.6-27b`) or xAI Grok (`grok-2-latest`)
- **Payments**: Razorpay Payment Links API
- **Cache**: in-memory dict keyed on normalized query + filters

Retrieval and generation are strictly separated: the LLM only explains the
items the retriever hands it; it never invents recommendations. Bookings hold
seats as soon as created and release seat conflicts with a 409.

## Setup

```bash
pip install -r requirements.txt
```

Optional (but recommended) environment keys — add them to a `.env` file in the
project root (loaded automatically; `.env` is gitignored):

```bash
GROQ_API_KEY="your-groq-key"                 # AI explanations & chat (preferred)
# or the xAI alternative:
export XAI_API_KEY="your-xai-key"            # Grok (xAI)
export XAI_MODEL="grok-2-latest"             # optional model override
export GROQ_MODEL="llama-3.3-70b-versatile"  # optional Groq model override
export RAZORPAY_KEY_ID="rzp_test_..."
export RAZORPAY_KEY_SECRET="your-secret"     # real payment; absent = simulated
```

Run the backend, then the frontend:

```bash
uvicorn backend.app.main:app --reload --port 8000   # backend
streamlit run frontend/app.py                       # frontend (http://localhost:8501)
```

> Showtimes are regenerated fresh (next 4 days) on every backend startup, so
> bookings are reset each restart — this keeps the demo schedule always current.

## Endpoints

- `GET /health` — liveness check
- `GET /genres` — known genres for the filter dropdown
- `POST /recommend` — `{"query": "...", "genre": "Sci-Fi", "item_type": "Movie", "top_k": 3}`
- `GET /movies` — full movie catalog
- `GET /theaters` — theater list
- `GET /dates` — upcoming show dates
- `GET /showtimes?movie_id=&show_date=` — showtime schedule
- `GET /seats?showtime_id=` — seat map with availability
- `POST /bookings` — `{showtime_id, customer_name, customer_email, seats: ["A1","A2"]}`
- `GET /bookings/{ref}` — booking status / e-ticket data
- `POST /bookings/{ref}/verify` — confirm a booking after payment
- `POST /chat` — `{message, history}` AI concierge

## Project layout

```
backend/app/
  main.py          # FastAPI app: recommendation + cinema + chat endpoints
  schemas.py       # Pydantic request/response models
  database.py      # SQLite: catalog + theaters/screens/showtimes/bookings
  vector_store.py  # embedding model + FAISS index build/search
  grok_client.py   # OpenAI-compatible xAI Grok client (chat + JSON)
  llm_explainer.py # grounded Grok explanations + validation fallback
  chat.py          # Grok concierge with live catalog/schedule context
  payment.py       # Razorpay payment links (mock fallback)
  cache.py         # in-memory cache keyed on normalized query
data/              # generated SQLite DB + seed data
frontend/app.py    # Streamlit UI
```
